# AGENTS.md

Annotate is a macOS menu bar app (Swift 6, AppKit, SwiftPM plus a generated Xcode project). This file is for agents and contributors. Keep it short, and update the enforcer table when an enforcer lands.

## Build and test

```sh
swift build
swift test                                                     # full suite, about 20 seconds
swift test --filter 'AboutViewTests|RedactionTests'            # one class
swift test --filter 'AboutViewTests|RedactionTests/testName'   # one test
```

Keep `AboutViewTests` in every filter. It runs first and sets up `NSApp`; without it the runner crashes in the first test's `setUp` because `NSApp` is nil (`TestHelpers.recordOpenWindows()`).

CI (`.github/workflows/ci.yml`) also builds and tests through Xcode. `Annotate.xcodeproj` is generated by XcodeGen and gitignored:

```sh
brew install xcodegen
xcodegen generate
xcodebuild -project Annotate.xcodeproj -scheme Annotate -configuration Debug \
  -destination "platform=macOS" test
```

Neither needs any interaction. Tests create real AppKit windows, so run them from a logged-in desktop session. SSH into a logged-in Mac should work too, but no run over SSH is on record. Xcode runs the tests inside `Annotate.app`, so they use your real Annotate preferences, and `SettingsViewTests` resets four of them. Prefer `swift test` locally. If `xcodebuild test` sits idle after `Test Suite 'All tests' passed` while other `xcodebuild test` runs share the Mac, add `-enableCodeCoverage NO` and a separate `-derivedDataPath`. This hang was seen once, with five runs at the same time, and the two flags were only tried together.

## Writing tests

- **Never start a real Sparkle updater.** Calling `startUpdater()` under xctest schedules a modal alert. In #79 a test that built its own controller and started it hung CI for 6 hours. Create test controllers with `startingUpdater: false` and assert on `updater.canCheckForUpdates`, as `AboutViewTests` does. `AppDelegate` also skips the start in Debug builds (#49, added for unsigned builds), which keeps `AppDelegateTests` from starting one.
- **Wait through the run loop.** Use `wait(for:)` from `AnnotateTests/TestHelpers.swift`, which runs `.defaultMode` so `asyncAfter` blocks drain. Don't block a `@MainActor` test on an `XCTestExpectation`, and don't run `.common`. To wait for a condition, poll with a deadline like `waitForPickerToDismiss()` in `OverlayWindowTests`, because CI can stall one run-loop pass for seconds (4c5fbd0).
- **Find layers and views by name, not position.** #91 inserted the dimming layer first, so a cursor test's `sublayers.first` became the dimming layer and the spotlight lost coverage while the test kept passing. #92 looks both layers up by name.
- **Isolate settings.** Inject `TestUserDefaults.create()` and call `TestUserDefaults.removeSuite()` when done.
- **Assert on pixels for drawing changes.** Render the view offscreen into a bitmap and check colors (see `renderedColor` in `RedactionTests` and `renderedPixelCount` in `OverlayViewTests`) instead of only checking model state.

## Verifying overlay changes

When a change affects what the overlay, toolbar, quick pickers, or cursor effects draw, post before and after screenshots in the PR, cropped to the affected area ([example from #73](https://github.com/epilande/Annotate/pull/73#issuecomment-5488286942)). Tests check the model; screenshots check the pixels.

1. Quit the installed Annotate. Debug builds share its bundle ID (`com.epilande.Annotate`), preferences, and global shortcuts. They never start the updater.
2. Build and open the base first. Run `git worktree add ../annotate-base origin/main`, then in `../annotate-base`:

   ```sh
   xcodegen generate
   xcodebuild -project Annotate.xcodeproj -scheme Annotate -configuration Debug \
     -destination "platform=macOS" -derivedDataPath build/dd build
   open build/dd/Build/Products/Debug/Annotate.app
   ```

3. Set up the state to show (tool, settings, display, light or dark mode), then capture:

   ```sh
   screencapture -x -T 3 -R 100,100,600,400 before.png   # region in points, 3 s delay
   screencapture -i -o before.png                        # or pick: drag a region, or Space for a window
   ```

   The terminal needs Screen Recording permission. Cursor effects stay visible during `screencapture -i` and follow its crosshair, so to capture them, place the cursor and use `-R` with `-T`. They hide only during the system Shift+Command+4 or 5 selection (#111).

4. Quit the base build. In your branch checkout, run the step 2 commands and capture again with the same state and region, saving `after.png`. Run one Debug build at a time: they share preferences and global shortcuts, so with two open you can capture the wrong one.
5. Add both images to the PR, labeled with the commit each came from.
